## Decisions Made & Rationale

- Four user decisions (interview): identical-to-editor look · editor grammar
  subset ships now · real anchors static (spans stay in editable DOM) ·
  single-branch big-bang.
- Review-driven, kept: **scheme-based link classification** (the old
  `includes('://')` heuristic misrouted `mailto:`/`javascript:`/`#frag`);
  **safety inside plugins** not at call sites (reader output is untrusted-
  author-served); **CSS allow/deny split** (`.wn-root` layout rule would clip
  reader pages); **cross-surface parity test** with one documented exception
  instead of string equality (serialization differs); `renderDocumentToHTML`
  stopped trimming + joins with `''` (pre-wrap fidelity).
- Minor plan deviations (all benign, noted during implementation):
  escapers live in `escape.ts` and `buildPluginMap` in `plugin-map.ts` (avoids
  plugin↔static-renderer cycle and keeps DOM code out of the SSR graph);
  `renderDocumentHtml(markdown, plugins)` takes plugins **explicitly** (no
  `defaultPlugins` default — same cycle reason); factory renamed
  `createViewerRenderer`→`createReaderRenderer`; browser verification used
  computed-style equality via CDP instead of screenshots.

## Architecture / Design Notes

- **One engine**: `src/core/tokenizer.ts` (line-oriented regex scan:
  anchored `^` defs consume whole lines, else `scanInline`) +
  `src/core/plugins/*` (each plugin has interactive `render()` → DOM and
  static `renderToHTML()` → string). The reader = `renderDocumentHtml`; the
  editor DOM = `renderLine`/`renderLines`. Both must stay structurally in
  sync — enforced by `surface-parity.test.ts`.
- Static shape: `div[data-line=N]` per source line (`<br>` when empty), text
  escaped, markers as dimmed `<span class="wn-punct">`, `data-raw`/`data-page`
  attributes on plugin elements.
- Link table (static): foldable-internal → `<a href="/{slug}"
  class="wn-wiki-link">`; `#`/`?` → plain relative anchor; scheme/`//` →
  `isSafeHref` gate (http/s get `target=_blank rel="noopener noreferrer
  nofollow"`, mailto gets plain rel, unsafe → escaped literal); unfoldable
  internal → escaped literal. DOM path keeps spans + `onNavigate` for
  internal only.
- **Security coupling to remember**: internal-href safety rides on
  `validateSlug`/`SEGMENT_RE` charset in `src/shared/slug.ts` (AGENTS.md
  slug-policy bullet says so). Reader styles: `layout.ts` composes
  `EDITOR_TOKENS_CSS + EDITOR_CONTENT_CSS + VIEW_CSS(chrome)`; server must
  import `core/static-renderer` directly, never the core barrel (node-smoke
  guards the seam).
- Coverage gate 80%; new core modules are covered (exclusions are bootstrap/
  type-only files).
