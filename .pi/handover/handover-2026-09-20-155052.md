## Blockers / Known Issues

- None blocking. Documented accepted trade-offs:
  - **Forward-only invariant:** blank rows created before this deploy persist
    (user declined the purge migration). Repository-layer `put()` still
    accepts blank content (test seeds rely on it) — the no-blank rule is
    enforced only in the HTTP routes.
  - **Cross-generation version aliasing:** recreation restarts `version` at
    1, so the delete guard holds per row-generation only. Same class as the
    pre-existing `putIfMatch` overwrite window; accepted + in plan Risks.
  - pg `deleteIfMatch` classification is two queries (non-atomic): a row
    created between them classifies as `conflict` rather than `missing`;
    client adopts the version (existing conflict-arm behavior).
  - **Reader browser cache:** anon visitors may see a deleted page up to 60s
    (their own `max-age=60`; server cache invalidates immediately). Documented.
  - Core `memory-page-store` (dev/test fallback) deliberately keeps blank
    pages in memory — no toast plumbing there (review decision).

## Decisions Made & Rationale

- **Route-level, not repository-level or DB-level enforcement:** repo `put`
  is a storage contract used by test seeds; a DB `CHECK` would break them.
  Documented as such in api.md to stop a future agent adding the constraint.
- **Version-guarded `deleteIfMatch` over get-then-delete:** reviewer proved
  a route-level get-then-delete loses to concurrent `putIfMatch` and can't
  produce a correct 409 payload. Stale blank saves 409 instead of destroying
  newer content.
- **Dual plan review caught 4 P1s that shaped rev. 2:** (1) the create
  overlay's POST sent no content → would break the button → redesigned as
  link + create-on-first-save; (2) unserialized saves → per-page token
  guard; (3) `createWithContent` 409 false-"Saved" → `onConflict`;
  (4) `memory-page-store` parity contradicted a pinned test + scope →
  dropped. Also fixed plan-text errors (guard ordering, toast-id semantics,
  "DB invariant" wording).
- **PUT-blank→204, POST-blank→400:** PUT is "make this the content" (blank =
  nothing here = delete, success); POST is "create a page" (a blank page is
  not a valid page).
- **Purge migration skipped (user):** forward-only invariant chosen over a
  destructive startup `DELETE FROM pages WHERE btrim(content)=''`.
- **Toast warning + dismiss-first:** `notifications.ts` returns early for a
  live same-id toast; Ctrl+S paths can stack "Saved" then "Page deleted".

## Architecture / Design Notes

- Save flow now: autosave → `ApiPageStore.save` → PUT `If-Match` → route:
  non-blank = write (200), blank = `deleteIfMatch` (204/409/404). Client
  state on delete: version dropped, buffer kept → next save POSTs → page
  back at v1 (undo-friendly, no tombstones).
- Page existence ≡ holds content: overlay link → auth shell (`exists:false`)
  → editor seeds `# {slug}\n\n` **in buffer only** (`editor-navigation.ts`
  loadPage / `editor-render.ts` 404-Create toast) → row created by first
  non-blank save.
- `src/shared/` remains env-agnostic; `isBlankContent` follows the `slug.ts`
  policy-module precedent.
- `deleteIfMatch` pg shape deliberately mirrors `putIfMatch` (one guarded
  write + one classification read).
